RL Fundamentals: CartPole & Q-Learning

Hey! I built this small project to get some genuine, hands-on experience with Reinforcement Learning before my interviews. Instead of just calling a black-box library like stable-baselines3, I wanted to write the core logic myself so I can actually explain how it works under the hood.

Goal: Train an agent to balance a pole on a moving cart using Q-Learning from scratch.

The Setup

I'm using the classic CartPole environment where a pole is balanced on a moving cart.

  • The State: What the agent sees at any given moment. In this case, it's a bunch of numbers telling us where the cart is, how fast it's moving, the angle of the pole, and how fast the pole is falling.
  • The Action: What the agent can actually do about it. It can either push the cart left or right. That's it.
  • The Reward: How we tell the agent it's doing a good job. It gets a point for every single frame the pole stays upright.
  • The Policy: The agent's overall strategy. Basically, its internal rulebook of "if I'm in this state, I should take this action."

How Q-Learning actually works here

Since CartPole's state is continuous (there are infinite possible angles and speeds), I first had to discretize it. Think of it like throwing those exact numbers into a set of buckets or bins. This lets us build a finite "Q-table"—which is essentially a giant cheat sheet.

The Q-table maps every possible state to the expected future reward of pushing left vs. pushing right. When the agent takes an action, it looks at the reward it got and uses the Bellman update rule to update its cheat sheet. It basically says: "Okay, let me update my old assumption with this immediate reward I just got, plus the best possible scenario I can see from my new position."

Why Epsilon-Greedy?

If the agent only ever took the action with the highest Q-value, it would get stuck doing the same dumb thing over and over because it never learned anything else.

That's where epsilon-greedy comes in. Epsilon is basically a "randomness dial."

  • We start it at 1.0, meaning the agent is just mashing buttons 100% randomly to explore the environment and see what happens.
  • Over time, we slowly turn that dial down (decay). As the agent learns more about the world, it starts trusting its Q-table more (exploiting its knowledge) rather than just blindly exploring.

Making Sense of the Reward Curve

If you look at the learning curve generated by the script, you can clearly see the agent's journey:

  • At the start: The rewards are terrible. The agent is mostly just guessing, so the pole drops almost immediately.
  • In the middle: It's a chaotic mess. You'll see massive spikes and drops as the agent occasionally stumbles into a good strategy, but then tries something else because the exploration dial is still somewhat high.
  • At the end: The curve climbs up and flattens out at a high score. The randomness dial is near zero, and the agent is actively using its polished cheat sheet to successfully balance the pole for a long time!

Running it yourself

If you want to run the training loop and see it learn from scratch locally:

pip install -r requirements.txt
python train.py

This will train the agent and spit out a fresh learning_curve.png so you can see the progress yourself.
